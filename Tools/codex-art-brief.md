# Codex 아트 작업 상시 지시서

이 문서는 Claude Code(과장)가 Codex(대리)에게 아트 작업을 위임할 때 **매 요청에 자동으로 붙는 고정 지시**다. 요청마다 다시 설명하지 않기 위해 분리했다.

## 0. 권한의 순서

1. **`Documents/Codex/Underwrite_아트_작업규칙.md`** — 아트의 최종 권한. 작업 시작 전에 읽는다.
2. **`Documents/Codex/Underwrite_8방향_애니메이션_자동생성툴.md`** — Unity 연결 도구 사용법.
3. **`Documents/Shared/Underwrite_기획서_v0.7.md`** — 세계관·캐릭터 설정. §17·§18이 아트 관련.
4. **`AGENTS.md`** — 프로젝트 루트. 작업 완료 범위.
5. 이 문서 — 위 문서들의 요약과 보고 양식.

**이 문서와 위 문서가 어긋나면 위 문서를 따르고, 어긋난 지점을 보고서 「미해결·주의」에 적는다.** 이 문서를 고치지는 않는다.

`Documents` 아트 영역의 문서는 Codex가 관리한다. 내용을 갱신했으면 보고서에 무엇을 바꿨는지 적는다.

## 1. 요청마다 다시 적지 않는 고정 제약

아래는 전부 아트_작업규칙에 있는 내용의 체크리스트다. 상세는 원문을 본다.

### 화풍

- 비도트 2D. 도트 화풍을 쓰지 않는다.
- 연하고 맑은 셀 채색, 따뜻하고 섬세한 선. 천과 조끼는 무광.
- 유광 하이라이트, 반짝이는 재질, 과도한 피부 광택 금지.
- 미세한 직물 무늬, 종이 질감, 입자, 빗금, 무작위 잔주름을 줄인다.
- 움직이지 않는 부위의 넓은 명암과 주름은 **프레임 간 고정**한다. 프레임마다 명암·외곽선을 다시 해석해 생기는 자글거림은 불합격 사유다.

### 일관성

- 같은 캐릭터의 방향·동작·프레임에서 얼굴, 머리 모양, 머리 크기, 체격, 선 굵기, 팔레트, 조명 방향을 유지한다.
- 승인된 성인 비율을 유지한다. SD·치비·큰 머리 비율로 바꾸지 않는다.
- 몸통·어깨를 임의로 넓히거나 근육을 더하지 않는다.
- 기준 원화: 주인공 `Assets/Images/Illustration/Underwrite_주인공_컨셉_v2.png`, 용사 5인 `Assets/Images/Illustration/Underwrite_용사5인_컨셉_v10.png`.
- 키 순서: 워리어 > 엘프 = 인간 남자 > 인간 여자 > 페어리.

### 방향

`S, SE, E, NE, N, NW, W, SW` 8방향. 폴더 이름도 이 코드를 쓴다.

| 코드 | 화면 방향 | DirectionX | DirectionY |
|---|---|---:|---:|
| S | 정면 | 0 | -1 |
| SE | 오른쪽 앞 대각선 | 0.707 | -0.707 |
| E | 오른쪽 옆면 | 1 | 0 |
| NE | 오른쪽 뒤 대각선 | 0.707 | 0.707 |
| N | 뒷면 | 0 | 1 |
| NW | 왼쪽 뒤 대각선 | -0.707 | 0.707 |
| W | 왼쪽 옆면 | -1 | 0 |
| SW | 왼쪽 앞 대각선 | -0.707 | -0.707 |

### 프레임과 캔버스

- 같은 동작의 모든 프레임은 **동일한 캔버스 크기·해상도·PPU·피봇 기준**을 쓴다.
- 캔버스 여백 차이는 캐릭터 키의 차이가 아니다. 실루엣이 커지는 동작에는 더 큰 공통 캔버스를 쓴다.
- 발밑 기준점을 고정한다. 앞뒤로 뻗는 발에 따라 프레임을 좌우로 재정렬하면 골반이 흔들린다.
- 머리·팔·다리의 실제 길이와 체격을 고정한다. 동작 때문에 달라진 실루엣을 키 변화로 오인해 프레임별로 확대·축소하지 않는다.

현재 확정된 규격:

| 대상 | 캔버스 | 발밑 기준점(Unity 아래쪽 좌표) | 프레임 |
|---|---|---|---|
| 주인공 Idle | 362×724 | (181, 13) | 8방향×6 |
| 주인공 걷기 | 640×724 | (320, 13) | 8방향×8 |
| 주인공 환호 | 512×960 | (256, 13) | 8방향×8 |
| 인간 여성 Idle | 512×724 | (256, 13) | 8방향×6, 실루엣 최대 620px |

### 알파와 가장자리

- PNG RGBA. 실루엣 바깥 **알파 0**, 내부 불투명, 가장자리만 좁은 안티앨리어싱.
- 바닥·접지 그림자, 광원 후광, 안개, 반투명 배경, 체크무늬 배경, 떠 있는 점·선을 **캐릭터 원본에 넣지 않는다.**
- 후처리 기준은 알파 32 미만 제거. 적용 후 머리카락·손가락이 잘리지 않았는지 **반드시 재검사**한다. 기준값을 일괄 높여 품질 문제를 숨기지 않는다.
- 본체와 떨어진 잡픽셀을 제거한다. 완전 투명 픽셀의 숨은 RGB도 정리한다.
- 검은 배경과 밝은 배경에서 테두리를 모두 확인한다.
- 생성 도구의 투명 배경 옵션만으로 잔점 0개를 보장하지 않는다. 연결 성분·알파·가장자리 접촉을 **검사하고 결과를 저장**한다.

### 하지 말 것

- 좌우 반전을 무조건 최종 원화로 쓰기. 비대칭 주머니·의상 위치가 틀어진다. 주인공의 묶인 갈색 주머니는 **해부학적 왼쪽 허리**에 고정이며 화면 기준이 아니다.
- 한 방향 그림을 돌려 다른 방향 원화를 대체하기.
- 앞 대각선과 뒤 대각선 혼동. 코·발·등으로 확인한다.
- Idle에 발만 흔들어 걷기를 대체하기. 걷기는 반대 팔·다리 교차, 접지·통과 자세, 무릎 굽힘, 체중 이동이 보여야 한다.
- 특정 대각선만 팔 교차 순서가 다른 결과를 완료로 처리하기.
- 정면만 만들고 8방향 완료라고 보고하기.
- 변형 코드로 완성 원화를 대신했다고 주장하기. 새 그림·표정·동작은 이미지 생성 도구로 만든다. 알파 잔점 정리는 코드로 해도 된다.
- 용사를 시장 거래자로 그리기. 일상 교류를 곧바로 후원자 정체 공개로 연출하기.

### 기존 아트를 수정할 때

- 기존 **파일명·해상도·프레임 수를 유지하고 PNG만 덮어쓴다.**
- `.meta`는 변경하지 않는다. Editor API로도 건드리지 않는다.
- 작업 전후 **메타 파일 해시를 비교**해 보고서에 개수를 적는다.
- 구조 변경(프레임 수 변경 등)이 필요하면 먼저 기존 Unity 연결을 보존할 방법을 제시하고 승인을 받는다. 임의로 바꾸지 않는다.

## 2. 납품

프로젝트에서 쓸 최종 PNG는 요청에 지정된 `Assets/...` 경로에 배치한다. 생성 도구 기본 출력 경로에만 남기지 않는다.

작업 기록은 `Outputs/<작업명>_v<N>/`에 남긴다. 기존 폴더의 구조를 그대로 따른다.

```
Outputs/<작업명>_v<N>/
  README.md                 작업 요약, 방향·프레임 순서, 재생 시간, 남은 차이
  generation_prompts.json   사용한 이미지 생성 프롬프트 전문
  verification.json         알파·연결성분·숨은 RGB·캔버스 접촉·프레임 수 검사 결과
  before.json               수정 전 상태와 메타 해시
  staging.json              배치 계획과 실제 적용 경로
  S/ SE/ E/ NE/ N/ NW/ W/ SW/   원본 프레임
  <작업명>_preview.png      전체 미리보기
```

승인 전 결과는 **시안으로 표시**하고, 완료한 방향 수·프레임 수·남은 차이를 명시한다. 기존 파일을 임의로 덮어쓰지 않고 동작·버전별 새 경로를 쓴다. 사용자가 정리·삭제한 실험용 리깅 자산은 복구하지 않는다.

## 2-1. 그리기 전에 무료 에셋부터 찾는다 (2026-10-18 사장님 결정)

**일러스트(초상·장면 그림)와 캐릭터(필드 스프라이트·애니메이션)를 뺀 모든 그림** — UI 틀·단추·아이콘, 배경 소품, 바닥·벽 질감, 효과 그림 등 — 은
이미지를 생성하기 전에 **웹에서 상업적 사용이 가능한 무료 에셋**을 먼저 찾는다.

1. 후보를 찾아 목록으로 보고한다. 항목마다: 이름 · 미리보기 링크 · 라이선스(원문 링크) · 상업 사용 가능 여부 · 출처 표기 의무 · 이 게임 분위기와 맞는 이유
   - **허용 라이선스만**: CC0, 또는 상업 사용과 게임 포함·수정이 명시된 것(예: 무료 상업 라이선스를 명시한 itch.io·OpenGameArt·Kenney 등). 「개인용만」, 「재배포 금지 조항이 게임 포함을 막는 것」, 라이선스가 불분명한 것은 제외
   - **유료는 후보에 넣지 않는다**(사장님 반려 — 돈 드는 것은 쓰지 않는다)
   - **게임 분위기와 맞아야 한다**: 비도트 일러스트풍, 따뜻한 영지 / 차갑고 어두운 지하, 판타지 중세. 도트(픽셀아트)·카툰 과장·현대 UI·밝은 모바일 캐주얼 풍은 제외
2. 과장이 검수한다. 통과한 것은 과장이 받아 들인다(라이선스는 `Documents/Claude/Underwrite_에셋_출처.md`에 적는다)
3. **과장이 반려하면 그때 그린다.** 반려 이유를 그리기 요청에 반영한다

이 순서를 건너뛰고 바로 그려야 하는 경우(맞는 무료 에셋이 있을 리 없는 이 게임 고유의 것 등)는 보고서 「미해결·주의」에 이유를 적는다.

## 3. Unity 연결 범위

요청에 **「Unity 연결까지」**라고 적혀 있으면 `Tools/Underwrite/Animation/8 Direction Builder`
(`Underwrite.Editor.AnimationTools.DirectionalAnimationBuilder.Analyze/Build`)로 다음까지 수행한다.

Sprite Library 카테고리·라벨 등록 → 방향별 클립 생성 → Animator 상태와 8방향 Blend Tree 연결 → 실제 프레임 재생 검증.

- 주인공: Library `Assets/SpriteLibrarys/Protagonist.spriteLib`, Controller `Assets/Animations/Controller/Controller.controller`, 클립 루트 `Assets/Animations/Clib`.
- 다른 캐릭터는 그 캐릭터의 에셋을 확인하거나 새로 만든다. **주인공 에셋을 덮어쓰지 않는다.**
- `DirectionX`·`DirectionY`와 기존 방향 좌표를 유지한다. 이미 등록된 동작은 실제 저장 경로를 확인해 갱신하고, 기본 `Generated` 폴더에 중복 생성하지 않는다.
- 직렬화 파일(`.anim`·`.spriteLib`·`.controller`)을 텍스트로 편집하지 않는다. Unity Editor API만 쓴다.
- 다른 캐릭터·동작의 카테고리·상태·전환 조건·GUID를 보존한다.
- 새 게임플레이 입력이나 발동·복귀 조건은 **요청에 있거나 기존 명확한 규칙이 있을 때만** 연결한다. 임의로 키를 정하지 않는다. 미연결이면 보고서에 적는다.

요청에 **「PNG까지」**라고 적혀 있으면 PNG 배치와 기록까지만 하고 Unity 연결은 하지 않는다. 그 경우 연결은 Claude Code가 한다.

## 4. 보고 양식 — 반드시 이 형식으로 끝낸다

최종 답변은 아래 형식만 쓴다. Claude Code는 최종 답변만 읽으므로, 여기 없는 내용은 전달되지 않는다.

```
## 결과
<한 줄 요약. 시안인지 완료인지 명시>

## 배치 경로
- <경로> | <장수> | <해상도> | <피봇>

## 검증
- 알파 분리 성분: <통과/실패 + 수치>
- 숨은 RGB: <통과/실패>
- 캔버스 접촉(잘림): <통과/실패>
- 프레임 수·방향 일치: <8방향 × N프레임 확인>
- 기존 .meta 해시: <N개 유지 / 변경 N개>
- 재생 확인: <반복/일회, 총 시간, 방향별 프레임 매칭 결과>

## Unity 연결
- <수행 여부. 했으면 Library 카테고리·클립·상태·Blend Tree 자식 수. 안 했으면 "요청 범위 아님">

## 기록
- Outputs/<폴더>

## 미해결·주의
- <규칙과 어긋난 점, 판단이 필요한 점, 남은 시안. 없으면 "없음">

## 다음 단계 제안
- <있으면. 없으면 "없음">
```

## 5. 판단이 필요하면 멈춘다

다음은 임의로 결정하지 않고 「미해결·주의」에 적어 되묻는다.

- 프레임 수·캔버스·피봇을 바꿔야 하는 경우
- 기존 Unity 연결을 끊어야 하는 경우
- 승인된 캐릭터 외형·비율을 벗어나야 하는 경우
- 새 입력·전환 조건이 필요한 경우
- 요청에 없는 다른 캐릭터·동작의 에셋을 건드려야 하는 경우

## 6. 알아 둘 것이 생기면 문서로 남긴다

작업하면서 **다음에 또 쓸 지식**이 생기면 `Documents/Codex/` 아래에 `.md`로 남긴다. 납품 보고(`Outputs/<폴더>/README.md`)는 그 작업 한 건의 기록이고, 이쪽은 작업을 넘나드는 지식이다.

남길 만한 것:

- 제작 기준이나 수치를 새로 정했을 때 (캔버스, 피봇, 9-slice Border, 색 토큰)
- 같은 실수를 되풀이하지 않기 위한 함정 (예: 배경 제거에서 갇힌 영역이 남는 문제)
- 도구와 파이프라인의 사용법, 재현에 필요한 매개변수
- 에셋을 찾아본 결과와 그 판단 근거

규칙:

- 파일 이름은 `Underwrite_<주제>.md`로 한다
- 이미 있는 문서에 해당하는 내용이면 **새로 만들지 말고 그 문서를 고친다**
- 문서를 만들거나 고쳤으면 보고의 「기록」에 그 경로를 적는다
- 아트 규칙 자체가 바뀌는 내용이면 `Documents/Codex/Underwrite_아트_작업규칙.md`에 반영한다. 그 문서가 아트의 최종 권한이다

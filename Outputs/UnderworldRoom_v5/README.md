## 원본·무료 에셋 조사·제작 방식

무료 상업용 자료를 먼저 조사했다. [asset_search.md](asset_search.md)에 제작자 원본·미리보기·라이선스 원문·확인일·무료 파일 범위·시점/축척/선/명암 판단을 적었다. 손그림 두 후보는 실제2048 이상 원본을 확인·수급하지 못했고, 확인한 고해상도 Poly Haven 후보는 규칙 대리석 격자였다. 이번 요청의 “맞는 것이 없으면 직접 그린다”에 따라 **내장 image_gen으로 직접 제작**했다. Cethiel·유료·외부 질감은 최종 바닥에 사용하지 않았다.

첫4K 요청도 실제 출력은1672×941였다. 이를2880×1620으로 늘리지 않았다. `floor_study_01.png`와 `floor_A.png`는 축척 검토 후 미사용. 최종 재료는 `sources/floor_E.png`, `floor_B.png`, `floor_C.png`, `floor_D.png`이며 각 원본 크기는 source_inventory.json에 기록했다. 각 장을 **한 번씩만 1:1로** 썼다. 겹친 구역의 RGB 차이와 어두운 줄눈을 고려하는 최소 비용 경로로 경계를 정해 부드러운 이중 줄눈이 생기는 크로스페이드를 피했다. `floor_native_mosaic.png`는 명도 마스크 전의 합성 원본이다.

새 바닥과 디테일 원화는 image_gen으로 만들었다. 코드는 원본 보존·접합·명도 조절·생성 디테일 추출·알파 정리·검수에 썼다. 깨진 판석 그림을 통째로 얹은 중간본은 테두리가 이중으로 보여 폐기했다. 최종은 기존 판석 면 안에 생성된 균열 선만 넣고 기존 외곽은 보존한다. 보수 판석은 서로 다른 기존 생성 원본의 면3개에+5/+7/+4를 적용했다. 생성한 보수 외곽 그림을 별도 돌처럼 얹지 않았다.

투명 디테일 원본은 재요청 후에도 낮은 알파의 후광이 남았다. 그 원본을 게임용 파츠로 납품하지 않고, 술자국의 생성 실루엣 중심만 표면 명도 마스크로 추출했다. 배수구는 철 테두리에 맞춰 잘라52×34로 축소했다. 마젠타 바탕의 균열 원본은 명시한 단색 키만 제거하고 추출했다. 최종 게임용 PNG의 알파32 미만 제거 기준을 일괄 높여 문제를 숨기지 않았다. 최종 room_plate는 모든 픽셀이255인 불투명 PNG이며, 기존12개 투명 사물은 수정하지 않았다.

generation_prompts.json에 시안·재시도까지 프롬프트 전문을 남겼다. sources에는 미사용 검토본도 보관하며 **납품 PNG는 루트의13종만**이다. `story_details.json`은 추가한3개 술자국,3개 균열 면,3개 보수 면, 배수구의 좌표와 크기를 기록한다. 각 생성 균열·술자국 모양은1회씩만 사용했다. 생성 바탕의 작고 자연스러운 흠집까지 수량3개라고 주장하지 않는다.

## 미해결·주의

- **Play 검수·사장님 시각 승인 전 시안.** 이번 요청대로 Assets에는 넣지 않았다. 기존 global intensity·촛불 Light2D 아래에서 동선·작은 술자국이 충분히 읽히는지는 과장 Play 캡처로 판단한다.
- 불규칙 생성 판석에는 작은 끼움돌과 일부40~80px·세로비0.5~0.8 밖의 형태가 남는다. 모든 판석의 치수와 “최대3장까지 연결되는 줄눈”을 전수 인증하지 않았다. 중앙 행/열 수치 통과만으로 개별 판석의 모든 기하 조건 통과라고 보고하지 않는다. 별도 추가한 균열/보수 면6개는 바운딩박스40~80px·세로비0.5~0.8로 골랐다.
- 벽 접지의25%는 기존150px 벽 그늘에 더한 표면 감쇠다. 구석의 추가 어두운 표면과 함께 작동하므로, 원본 면 대비 전체 감쇠가 모든 지점에서25%인 것은 아니다. 빛 번짐은 없다.
- 무료 후보 원본의 로컬 다운로드는 연결 거부로 실패했다. 라이선스 원문·첨부 목록 확인과 실제 원본 크기 확인을 구분했다. 이번 특정 요청의 직접 제작 허용을 사용했으며, 이후 다른 환경 작업의 무료 후보 검수 순서를 생략하는 근거로 쓰지 않는다.
- 상시 지시서의 통상 Assets 배치와 달리 이번 요청은 Outputs만 명시했다. 이를 적용했다. 정적 환경이므로 캐릭터8방향 Unity 자동 연결 범위는 해당 없음.

## 재현·연결 담당자

`python Outputs/UnderworldRoom_v5/build_v5.py` → `python Outputs/UnderworldRoom_v5/deliver_v5.py` → `node Outputs/UnderworldRoom_v5/verify_components.mjs`. 최종 기술·육안 확인 뒤 layout.pending.json을 layout.json으로 공개했다. 원본 생성 재호출은 재현 과정에 필요하지 않다. before.json은 최초 스냅샷이므로 `--snapshot`으로 덮어쓰지 않는다.

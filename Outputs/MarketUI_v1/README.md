## 판단과 배치 근거

- 핵심 비교를 먼저 만든다. 완성형에서 정보 기록을 항상 보이는 오른쪽 열에 두고 최근 4건을 읽게 한다. 34틱 중개인 누설, 30틱 비공개 서신, 24틱 공식 기록, 20틱 공개 소문의 순서다. 최신순을 유지하되 비공개 항목은 봉인 아이콘·황토색 바탕·진한 왼쪽 선·명시적 문구로 구분한다. 색만으로 공개 여부를 구별하지 않는다.
- 완성형의 기본 기록 범위는 전체 시장이다. 선택 종목으로 좁힐 수 있으나 다른 종목의 비공개 정보가 필터 뒤에서 사라진 사실을 알 수 있도록 전체 비공개 건수는 패널 머리에 유지한다. 4건 이후는 패널 내부 스크롤/이전 기록 보기로 접근한다. 고정 화면에 모든 기록을 축소해 넣지 않는다. 새 항목이 와도 읽던 스크롤 위치를 강제로 바꾸지 않고 신규 건수를 표시하는 구현을 제안한다.
- 축소판에서는 세 종목의 현재가·등락을 유지하고 선택 종목의 보유·평단만 펼친다. 현금·총자산은 상시, 평가액·실현손익은 자산 상세 보기로 접는다. 선택 종목의 핵심 정보 2건(비공개 30틱과 공개 20틱)을 나란히 읽게 해 정보 차이를 학습한다. 전체 기록 보기는 처음부터 열 수 있다. 정보 자체를 튜토리얼 진행 보상으로 잠그지 않는다.
- 축소판→완성형은 표시 밀도 변화다. 특정 날짜·퀘스트·유료 해금 조건을 만들지 않았다. 실제 단계 전환 시점은 구현 시 기존 튜토리얼과 연결한다.
- 차트는 선택 종목 하나만 크게 표시한다. 가격 목록을 누르면 차트·주문·선택 종목 기록이 같은 대상으로 바뀐다. 선 그래프와 0~96틱 축을 사용하고 아직 오지 않은 구간은 빈 공간으로 둔다. 주가 수치는 1자리 소수, 장중 등락은 개장가 대비 1자리 소수다. 평단·보유가 없는 경우 평단은 —로 표시한다.
- 거래량 막대를 넣지 않았다. 기획서 §5에는 거래량이 있으나 현재 코드에는 틱별 거래량 이력이 없다. Liquidity는 가격 충격의 분모이며 거래량이 아니다. 완성형에 현재 유동성만 보조로 두고, 거래량은 데이터를 추가한 이후의 확장 슬롯으로 남긴다. 존재하지 않는 데이터를 그려 판단 근거로 만들지 않기 위한 결정이다. 원정 상태 역시 독립 상태 필드가 없어 현재는 정보 기록의 사건 문구로 전달한다.
- 시장가 주문은 매수/매도 선택, 정수 수량, 예상 체결가·금액, 실행 버튼으로 구성한다. 기본 보이는 수량은 10주, 초기 프로토타입의 1~100주 범위를 유지하는 안이다. 수량 영역은 직접 입력과 증감 버튼을 같은 값에 연결한다. 주문 성공은 실행 아래에 수량·체결가·금액으로, 실패는 같은 위치에 사유로 표시한다. 수수료·지정가·공매도·배당·후원 UI는 없다.
- 휴장은 암적색 공지와 닫힌 출입문으로 드러낸다. 마지막 거래가·그 기준 평가액을 읽을 수 있고 주문만 비활성이다. 비활성 사유를 버튼 안에 쓴다. 정보 수신·세계 시간·배속은 계속 사용할 수 있다. 임의의 재개장 카운트다운·예약 주문·새 이동 버튼을 추가하지 않았다. 폐장은 같은 주문 잠금 규격에 상태 문구를 폐장으로 바꾸며, 영주 조사 연출은 휴장에만 사용한다.

## 1920×1080 구현 기준

생성 시안의 장식과 수작업 같은 비대칭은 분위기 참고다. 아래 수치는 UI Toolkit에서 정렬할 권장 고정 규격이며, 그림의 모든 테두리 픽셀을 그대로 복제하라는 뜻은 아니다. 글자·숫자에 종이 질감을 덮지 않는다.

## 좁은 화면에서 접기

| 가용 너비 | 재배치 |
|---|---|
| 1600px 이상 | 완성형 3열. 가운데 차트가 남은 폭을 받으며 정보 열 최소 400px, 종목 최소 360px |
| 1280~1599px | 2열: 왼쪽 차트/주문, 오른쪽 정보 400px. 종목은 상단 3개 선택 카드로 접는다. 자산은 현금·총자산과 상세 버튼. 시간·배속은 머리 둘째 줄로 이동 |
| 960~1279px | 세로 한 열. 종목 선택→현재가/보유→가격/정보 탭→주문. 기본 탭은 정보이며, 가격 탭에서도 나만 아는 정보 건수와 최근 한 줄을 유지. 주문은 하단 접이식 패널로 열고 닫는다. 정보 본문과 주문이 겹치지 않게 공간을 확보 |
| 960px 미만 또는 낮은 창 | 한 열 유지, 본문 영역 세로 스크롤. 정지·개장 상태·선택 종목은 머리에서 유지. 글자 크기를 비례 축소하지 않으며, 모든 기능을 수평 잘림 없이 접근 가능하게 한다. 휴장 경고는 모든 탭 상단 유지 |

최소 본문 20px, 각주 18px, 누름 영역 최소 48×48px. 긴 종목명은 2줄로 줄바꿈하고 현재가를 가리지 않는다. 이는 재배치 설계 설명이며 좁은 화면의 실제 UI 구동 검증을 수행한 것은 아니다.

무광 목재는 화면 외곽에만, 황동은 작은 모서리·인장에만 쓴다. 본문은 깨끗한 장부 면을 유지한다. 캐릭터 원화의 부드러운 채색과 따뜻한 선을 이어받되 UI의 중요한 숫자는 평평하고 대비 높은 면 위에 둔다. 이미지의 붓칠·조명으로 생긴 개별 픽셀은 HEX 토큰과 정확히 같지 않다. 상승은 적갈색+▲+, 하락은 청색+▼−, 보합은 잉크색+—를 쓴다. 공포의 청색 표식은 텍스트로 장세임을 밝혀 종목 하락과 구분한다.

## 정보 출처와 세 가지 상태

| 출처 | 표시할 판단 근거 | 뜻 |
|---|---|---|
| 여관 소문 | 소문 | 말이 돌고 있음, 진위 보장 없음 |
| 길드 기록 | 공식 기록 | 공식 기록이라는 근거가 있음, 미래 수익 보장 없음 |
| 사적 서신 | 당사자 전언 | 개인 경로로 들은 내용, 공개 여부와 진위는 별개 |
| 시장 게시판 | 공개 전언 | 시장이 접한 정보, 사실 확정이라는 뜻은 아님 |
| 중개인 누설 | 확인 필요 | 이해관계자의 전언, 교차 확인 필요 |

코드에는 신뢰도 수치가 없으므로 확률·별점·새 신뢰도 점수를 만들지 않았다. 이 문구는 출처에 대한 정성 설명이다. IsPublic이 정보의 공개 표식을 결정하고 Stage가 소문/보고/결과의 성격을 결정한다. Stage_Outcome이 공개된 경우에만 결과라는 문구를 쓸 수 있다. TruthOnly 사건과 TrueValue·TargetPrice는 보이지 않게 한다. 공개와 진실을 같은 아이콘으로 표현하지 않는다.

30틱 서신의 가격 미반영은 34틱 예시 상황에서 유효하다. 이후 38틱에 동행 취소가 공개되면 과거 사적 서신의 IsPublic=false만으로 관련 사실이 영원히 가격 미반영이라고 표시하면 안 된다. 현재 데이터에는 사건 간 동일 사실 연결 ID가 없으므로, 일반 UI에서는 과거 항목을 '당시 시장 미공개'로 표현하고 현재도 미공개라는 판단을 자동으로 단정하지 않는다. 시안의 비공개 건수 역시 현재 스냅샷 34틱의 1건이다.

예시 화면은 34틱, 5분/틱이므로 경과02:50이다. 현재가는 셀라58.0, 브란120.0, 블랙무어88.0을 가정했다. 초기 개장가42/120/75 대비 +38.1%/0.0%/+17.3%다. 보유20주×58 + 5주×120 = 평가액1,760. 현금3,240 + 평가액1,760 = 총자산5,000. 실제 초기 자금은 코드의500이며 시안의 자산 수치는 가상의 이후 계좌다. 시드 재생 결과나 실제 실행 캡처로 주장하지 않는다.

매수10주/현재가58/유동성62/ORDER_IMPACT_SCALE0.9이면 충격=58×0.9×10/62=8.41935, 예상 체결가=58+충격/2=62.20968, 금액622.09677 → 표시62.2/622. 단순 현재가×수량으로 견적을 내면 안 된다. 매도는 충격의 부호가 반대이며 PRICE_FLOOR를 적용한다. 실제 주문 시 서버가 아니라 현재 MarketSimulation의 결과를 그대로 표시한다. 정지 중에는 코드상 Phase_Open이면 주문이 허용되므로 독자적으로 정지 중 거래 금지를 만들지 않는다. PlayerAtMarket=false 또는 휴장/폐장/거래 불가 종목은 코드의 실패 사유를 표시한다. 휴장 시에도 사건은 진행되지만 가격 이력에 새 거래점을 추가하지 않는다.

시안의 사건은 PrototypeScenario의 20/24/30/34틱 문구를 짧게 줄인 표현이다. 38틱 이후 결과나 미래 사건을 미리 노출하지 않았다. 원문 전체를 보려면 실제 InfoEntry.Headline을 사용한다. 차트 곡선은 분위기 설명용 예시이며 정확한 34틱의 x위치·샘플 개수는 생성 이미지에서 보장하지 않는다. 실제 구현에서는 오늘의 PriceHistory를 0~96틱 축에 수학적으로 배치하고 현재 틱 이후를 비운다. 휴장 시안의 차트는 과거 거래 기록만 표시하는 별도 구획이며 현재 휴장일 틱과 과거 가격 샘플 틱을 혼합하지 않는다.

## 보존·검증과 전달

원본6장은 originals/에 보존했다. 이미지 생성 결과는1672×941이어서 납품 이미지4장을1920×1080 RGBA로 크기만 정규화했다. 조각8장은 원본 보드에서 여백을 포함해 사각 추출하고 폭920px로 정규화했다. 미리보기는 납품4장을2×2로 배치했다. 새 그림·글자 수정은 기본 image_gen을 사용했으며, 코드로 그림을 새로 그리거나 게임 소스를 수정하지 않았다. 프롬프트 전문6개와 참조 입력은 generation_prompts.json, 원본·납품 관계는 staging.json에 있다. 상시 지시서·기획서·아트 규칙 문서는 변경하지 않았다.

화면 PNG는 배경이 있는 불투명 UI 시안이다. 캐릭터 컷아웃의 바깥 알파0 규칙을 UI 화면 전체에 적용하지 않는다. 분리 알파 성분·숨은RGB는 불투명성 검사로 확인하고, 화면 외곽 배경의 캔버스 접촉은 의도된 것으로 분류한다. 자동검사 수치는 verification.json에 기록한다. UI 상호작용·좁은 화면 재배치·SpriteResolver 재생은 수행하지 않았다.

미해결: 사용자 승인 전 시안이며 이미지마다 미세한 문장 배치·문양·장식 밀도가 다르다. 특히 차트 곡선은 정확한 데이터 플롯이 아니다. 구현은 이미지의 곡선을 트레이스하지 말고 위 데이터 규격을 따른다. 생성 이미지의 서체·색·카드 간격은 구현 토큰으로 정돈해야 한다. PNG를 런타임 화면 전체에 깔아 조작 UI를 대체하지 않는다. 거래량과 독립 원정 상태를 보여주려면 원천 데이터가 먼저 필요하다. 이는 임의의 새 게임 규칙을 적용한 결과가 아니다.

기록 보존 메모: 폴더 확인 중 이번 생성과 다른 내용의 프롬프트 기록을 발견해 generation_prompts.existing_snapshot.json에 보존했다. 이번 결과의 프롬프트 전문6건은 generation_prompts.json, 선택 원본은 staging.json이 기준이다. source/와 before_current.json은 이번 작업의 납품 근거로 사용하지 않았고 변경하지 않았다.

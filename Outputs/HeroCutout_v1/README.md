## 가공과 보존

processing.cjs와 parameters.json에 실제 알고리즘·인물별 원본 영역·내부 빈 공간·반투명 영역을 기록했다. run.cjs로 PNG와 검정/흰색/지하실 미리보기를 다시 만들 수 있다.

외부와 연결된 밝은 배경 및 푸른 바닥 그림자를 플러드로 제거하고 인물 본체를 분리했다. 머리카락/검 손잡이 내부의 갇힌 흰 배경은 수동으로 지정한 영역 안에서 같은 기준으로 제거했다. 가장자리 2px의 흰색 매팅은 가까운 내부색을 사용해 알파를 추정했다. 엘프 얇은 천과 요정 날개는 수동 지정 영역에 부드러운 경계를 적용해 투명도를 추정했다. 완전 투명 픽셀 RGB=0, 알파32 미만 제거.

불투명 픽셀 RGB는 원본과 채널 차이 0개다. 반투명 픽셀 RGB는 흰 배경 성분만 역합성했으며, 모든 생존 픽셀을 흰색 위에 재합성했을 때 원본 대비 채널 오차 0이다. 이는 원래 선과 색의 흰 배경 위 외관을 유지한다는 검증이며, 원래의 진짜 알파가 복원되었다는 증거는 아니다.

6장 모두 알파>0의 8연결 성분 1개, 분리 잔점 0개, 숨은 RGB 0개, 캔버스 접촉 0개다. 최종 사방 여백은 각각 8px다.

## 픽셀 수 해석과 남은 한계

비흰색은 min(R,G,B)<245로 정의했다. 원본 크롭에는 그림자·이웃 인물·밝은 배경 질감도 포함되므로, 위 숫자의 감소를 인물 손실로 해석할 수 없다. 추정 본체 마스크 내부에서도 알파32 미만 경계 정리와 발밑의 푸른 그림자 제거로 위 표 마지막 열만큼 제외되었다. 제거 오버레이에서 큰 신체 부위나 머리 끝/날개가 사라지지 않았음을 육안 확인했지만, 단일 RGB 원본과 추정 마스크만으로 인물 픽셀 손실 0개를 증명할 수는 없다.

흰색에 합성된 RGB 한 장에는 원래의 전경 RGB와 알파가 따로 저장되어 있지 않다. 따라서 반투명 드레스/날개의 진짜 불투명도와 어두운 배경에서의 정확한 색은 유일하게 복원할 수 없다. 현재 결과는 원본의 흰 배경 외관을 보존한 추정 알파 시안이며 확대 비교를 통해 검토해야 한다.

아트 작업규칙 §6의 일반적인 내부 불투명 기준과 달리, 이번 요청에서 명시한 얇은 천/날개 보존을 위해 해당 부분의 내부 반투명을 허용했다. 일반적인 Assets 납품·Unity 연결 범위 대신 이번 요청의 명시적 Outputs 전용·PNG까지만 범위를 적용했다. 상시 지시서는 수정하지 않았다.

원본 두 장 SHA256 동일. 작업 시작 시 존재한 Assets/**/*.meta 445개는 모두 해시 동일, 변경/삭제 0개다. 재검사 시 신규 .meta 5개가 관찰되어 전체는450개였다. 본 작업은 Assets에 쓰지 않았고 신규 파일도 수정/삭제하지 않았다. 목록: Scripts/UI/UI_Popup.cs.meta, Temp/ui_popup.png.meta, Temp/ui_popup2.png.meta, Temp.meta, UI/CommonPopup.uxml.meta. 따라서 기존 파일 무변경은 통과하지만 작업 중 Assets 파일 목록 전체가 동일하지는 않았다.

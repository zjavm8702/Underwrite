## 최종 파일

유형은 leader, archer, shield, porter. 방향은 S, SE, E, NE, N 순서다.

- {유형}/Idle/{방향}/{방향}_00.png ~ _05.png: 본체120장, 362×724 RGBA.
- {유형}/Walking/{방향}/{방향}_00.png ~ _07.png: 본체160장, 640×724 RGBA.
- 각 본체 옆 *_mask.png280장: 같은 크기, 천 부분 흰색 불투명, 나머지 RGBA0. 마스크가 본체 알파를 초과하는 픽셀0.
- SW/W/NW 원화는 만들지 않았다. 요청대로 코드에서 SE/E/NE를 좌우 반전하고 마스크도 함께 반전한다.
- 전체560장의 실제 경로·SHA256은 staging.json에 있다. 방향/프레임 이름은 최종 납품 폴더를 기준으로 한다. sources와 reference의 이미지는 납품 프레임이 아니다.

## 좌표·축척·시간

Idle 기준점은 Unity 아래쪽(181,13) / PNG 위쪽(181,711), Walking은(320,13)/(320,711)이다. 이는 PNG상의 공통 배치 기준이며 Unity 설정을 변경한 것이 아니다. PPU100은 주인공 메타에서 확인한 전달 기준이다.

걷기는 발끝/무기/짐의 전체 bbox 중심으로 매 프레임 재정렬하지 않는다. 가장 긴 연결 구간으로 추정한 몸통 밴드(원본 높이47~52%)를 첫 Idle의 발 영역(하위15%)과 연결해 공통 기준점을 정한다. 방향·동작마다 공통 배율을 유지하며 포즈별 확대/축소는 하지 않는다. 폭이 넘지 않도록 방향 전체에 동일한 배율을 적용했다. 단장은 좁은 Idle 캔버스와 발 기준을 함께 지키기 위해 짧은 어깨 망토로 재생성했다.

Idle의 y≥480 하체는 해당 방향 첫 Idle로 고정했다. 20개 Idle 시퀀스 모두 이 영역의 RGBA 변경0픽셀, 발 위치 X/Y 편차0px다. Walking은 발 실루엣 아래끝 Y의 방향 내 최대 편차1px다. 이는 골반·명암의 모든 픽셀이 동일하다는 뜻이 아니다.

Idle 반복:900,350,80,110,120,700ms=2260ms. Walking 반복:100ms×8=800ms. timing.json은 v1의 characters→동작 구조에 directions→방향 키를 추가했으며 각 frames 항목에 file, mask, ms를 기록한다. 유형별 timing.json도 있다.

주인공 이동 코드 PlayerCharacterInput.cs의 MoveSpeed는3유닛/초다. 같은 이동 속도를 쓸 때 신규 걷기 한 바퀴 이동 거리는3×0.8=2.4유닛(PPU100에서240px)이다. 이는 시간표와 동일 속도 조건의 계산이며 실제 NPC 런타임 이동을 측정한 값은 아니다. 기존 주인공 Walking_E.anim만 StopTime0.7초이고 S/SE/NE/N은0.8초다. 신규 NPC는 전 방향0.8초로 통일했으며 기존 클립은 수정하지 않았다.

## 단 색 천

단장: 짧은 어깨 망토 / 궁수: 젖힌 후드·카울 / 방패병: 허리 천 / 짐꾼: 스카프. RGB가 동일한 무채색으로 정리하고 유형별 공통 명도 계수로 명암을 유지했다. 최종 마스크 영역의 회색 중앙값은 단장179, 궁수178, 방패병179, 짐꾼179(약70%)이다. 마스크 내 원화의 RGB 채널 차이0, 빈 마스크0.

마스크는 색만으로 고르지 않고 천의 위치와 연결 성분을 함께 사용한다. 피부·바지·금속·침낭·밧줄을 오염시키던 중간본은 최종 원본 재배치로 교체했다. team_colors_and_W.png는 마스크 위치에만 원화RGB×단색을 적용한 예시이며 원화 자체에 빨강/초록/파랑을 저장한 것이 아니다. 가장자리의 좁은 AA를 제외한 불투명 내부가 마스크다.

## 검증

- 본체280장 모두 연결 성분1, 분리 잔점0, 숨은 RGB0, 캔버스 접촉0.
- 마스크280장 모두 흰색 불투명/투명 형식, 본체 알파 밖0, 숨은 RGB0, 캔버스 접촉0, 빈 마스크0.
- 알파32 미만은 제거하고 내부 불투명도를 정리했다. 손·신발·머리·활·짐이 캔버스에 닿지 않는지 전수 검사했다.
- 40개 APNG의280프레임은 원본과 IHDR/압축 IDAT 스트림이 같으므로 디코딩 결과 RGBA가 동일함을 확인했다. 프레임별 지연과 반복 횟수도 검사했다. 이 검사는 실제 화면 재생을 육안 확인한 것과 구분한다.
- 참조 주인공 폴더의 기존 .meta203개 SHA256 유지, 변경0·누락0. Assets 쓰기 없음.
- verification.json이 최종 집계, alignment_verification.json은 하체·회색·주기 거리의 상세다. verification_working.json은 불합격 중간 기록이며 최종 판정에 사용하지 않는다.

## 인계·주의

1. 사용자 시각 승인 전 시안이다. 실제 게임 크기에서 시간적 명암 안정성, 체중 이동·루프 연결, 장비 세부와 연령 인상을 최종 판정해야 한다. 파일 검사를 실시간 재생 검증으로 부르지 않는다.
2. 기본 문서의8방향·Unity 연결 범위보다 이번 명시 요청인5방향·좌우 반전·PNG까지만·Assets 금지를 우선 적용했다. 공통 아트 규칙을 변경한 것은 아니다.
3. 기존 주인공 E걷기0.7초와 나머지0.8초 차이는 남아 있다. 신규0.8초 시간표와 게임에서 비교할 때 이 차이를 고려한다.
4. 기본 8 Direction Builder는8방향을 요구하고 폴더의 이미지도 읽는다. 이번5방향 구조와 같은 폴더의 *_mask.png를 그대로 기본 스캔에 넣지 않는다. 연결 담당은 본체와 마스크를 구별하고 반전 시 둘의 좌표·피봇·Rect를 맞춰야 한다.

## 제작 기록과 재현

기본 제공 image_gen 사용, CLI/API fallback 없음. 전체30회 생성·보정 프롬프트는 generation_prompts.json, 원본·mtime·SHA256은 generation_manifest.json과 sources/generation_*.png에 보관했다. 원본 mtime은 생성 시작 시각이 아니다. 최종 선택 원본·공통 배율·좌표는 각 유형의 {방향}_placement.json을 따른다.

새 그림과 동작은 이미지 생성 도구로 제작했다. 코드는 분할·공통 배율·정렬·Idle 정지 하체 합성·마스크와 회색 정리·알파 청소·검증·미리보기에 사용했다. 파츠 변형 코드로 새 걷기 그림을 대신하지 않았다.

pipeline.mjs/anchors.mjs/rebuild_final.mjs/finalize.mjs/delivery_audit_worker.mjs가 최종 재현 코드다. rebuild_final.mjs는 선택 원본에서 PNG·마스크·APNG·검증을 갱신한다. finish_delivery_worker.mjs는 Worker에서 재생성과 추가 검사를 순서대로 실행한다. 큰 PNG 루프는 node_repl 메인 실행의 시간 제한을 피하도록 node:worker_threads에서 수행했다.

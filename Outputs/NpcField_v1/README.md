## 배치와 재생

각 사람 폴더의 Idle/Work/Give/S_00.png부터 S_05.png가 최종 개별 프레임이다. 모두362×724 RGBA, 기준점은 Unity 아래쪽(181,13) / PNG 위쪽(181,711). 인물별 공통 배율로 제작했고 Idle bbox 높이는 주인공699px 대비646~698px, 92.42~99.86%다. 한 동작 내의 프레임을 따로 확대·축소하지 않았다. PNG 단계이므로 실제 Unity PPU·피봇 설정은 하지 않았다.

Idle은 반복 900,350,80,110,120,700ms =2260ms. Give는 일회200,140,180,360,180,240ms =1300ms. 경비 Give는 물건 전달 대신 고개 끄덕임이다. Work는 모두6프레임 반복이며 다음 시간표를 사용한다. 최종값은 루트와 인물별 timing.json에 있다.

## 검수 결과

- 필드180장과 초상20장 모두 본체 연결성분1, 분리 잔점0, 숨은 RGB0, 캔버스 접촉0. 알파32미만0, 내부 불투명·가장자리 AA 확인.
- 각 동작6장 간 고정 하체(y≥552)의 RGBA 변경0픽셀, 발 위치 지표의 X/Y 최대 편차0px. 이는 동작 내 검사이며 상체 연기의 모든 픽셀이나 서로 다른 동작의 옷 모양을 동일하게 만들었다는 뜻이 아니다.
- 초상 보존 마스크 안 원본 대비 변경0픽셀(0%), 같은 사람4장 간 몸·옷·전체 알파 변경0픽셀. 마스크 이미지와 다각형 좌표를 함께 보관한다.
- 기존 .meta686개 모두 해시 유지, 변경0·누락0. 기존 갑옷 초상20장도 모두 SHA256 유지.
- 30개 APNG의180프레임 RGBA를 개별PNG와 대조해180/180 일치. 프레임별 ms와 반복/일회 횟수도 파일에 기록했다.

## 미해결·주의

1. 브라우저 도구에 연결된 브라우저가 없고 iab 열기도 Browser is not available 오류로 실패해 실시간 화면 재생을 육안 검증하지 못했다. APNG 디코딩·순서·시간 검증을 실제 화면 재생 검증이라고 보고하지 않는다.
2. 사용자 시각 승인 전 시안이다. 상체·얼굴의 미세 윤곽 차이와 호흡·작업 루프의 인상, 약하게 내미는 견습 Give의 가독성은 실시간 화면 검수가 남아 있다.
3. 상위 문서의 기본8방향·Unity 연결 완료 범위와 이번 명시 요청이 다르다. 이번 S한 방향·PNG전용·Assets 금지를 우선 적용했다. 걷는 용병8방향은 제작하지 않았다.

## 제작·재현 기록

기본 제공 image_gen 사용. generation_prompts.json은 사용한 전체 프롬프트·참조, generation_manifest.json은 저장 시각·원본 해시, sources/는 최초본과 보정본이다. 시각이 요청 단계에서 누락된 항목은 원본 수신 파일mtime을 별도 기록했으며 이를 생성 시작 시각으로 취급하지 않는다. 새 동작을 코드 변형으로 그리지 않았다. 코드는 생성 원화의 분할·동일 배율 배치·정지 부위 합성·알파 정리·검증·미리보기에 사용했다.

최종 검증은 verification.json, 납품200장과 해시는 staging.json을 우선한다. verification_working.json은 중간 분할 상태다. 재현 코드는 pipeline.mjs, split_corrected.mjs, split_last.mjs, split_give_right.mjs, build_portraits.mjs, build_reviews.mjs, finalize.mjs다. 전체 재생성은 원본·참조 해시 확인 후 rebuild_final.mjs를 사용한다.

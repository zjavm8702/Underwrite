# Underwrite 아트 작업 규칙

작성·갱신: 2026-10-16  
게임: 《지하거래소의 후원자》  
적용 범위: 주인공·용사·NPC 원화, 필드 스프라이트, 감정·상호작용 애니메이션, Unity 전달 자료

이 문서는 대화에서 확정한 아트 방향을 보관한다. **비도트 8방향 스프라이트 애니메이션**이 현재 제작 기준이다. 기획서도 v0.4(2026-10-16)에서 §18을 8방향 프레임 교체 기준으로 갱신했으므로 더 이상 어긋나지 않는다. v0.3 이전의 ‘4방향·리깅 중심’ 기술은 과거 판이며 적용하지 않는다. 생성된 시안과 사용자 승인 완료 원화는 구분해서 기록한다.

## 최신 완료 범위 — 2026-10-16 확정

사용자 지시: **앞으로는 현재 진행한 자동 연결 단계까지 에이전트가 마무리한다.**

1. 요청된 캐릭터·방향·동작의 스프라이트를 제작한다.
2. 비율·화풍·동작 순서·알파·프레임 정렬을 확인하고 실제 프로젝트 폴더에 PNG를 배치한다.
3. 해당 캐릭터의 Sprite Library에 방향별 카테고리와 프레임 라벨을 등록한다.
4. SpriteResolver를 기록한 방향별 애니메이션 클립을 만들고 반복 여부·프레임 시간을 설정한다.
5. 해당 Animator Controller의 상태와 8방향 Blend Tree를 연결한다. `DirectionX`·`DirectionY`와 기존 시퀀스를 유지한다.
6. 실제 프레임 재생과 라벨 매칭, 기존 관련 없는 연결·에셋 보존을 검증한 뒤 적용 경로와 결과를 기록한다.

PNG·미리보기만 전달한 뒤 Library 등록·클립 녹화·Blend Tree 연결을 사용자에게 넘기는 것으로 완료 처리하지 않는다. 위 단계는 이후 애니메이션 제작 요청에 포함된 작업 범위이며 매번 적용 허락을 재확인하지 않는다. 기존 아트의 수정만 요청받았고 연결이 이미 올바르면 PNG만 교체하여 기존 연결을 유지한다.

자동화 도구: `Underwrite.Editor.AnimationTools.DirectionalAnimationBuilder.Analyze/Build`, 메뉴 `Tools/Underwrite/Animation/8 Direction Builder`. 사용법은 `Underwrite_8방향_애니메이션_자동생성툴.md`를 따른다. 이미 등록된 동작의 실제 클립·Library·Controller 경로를 확인한 후 갱신하여 중복 에셋을 만들지 않는다. 다른 동작·캐릭터와 기존 전환 조건은 보존한다. 새로운 게임플레이 입력이나 발동·복귀 조건은 요청 또는 기존 명확한 규칙이 있을 때 연결한다.

기존 텍스처 `.meta` 보존 규칙은 계속 적용한다. 반면 이 작업 범위에 필요한 `.spriteLib`·`.anim`·`.controller` 연결 변경은 허용된 작업이며 반드시 Unity Editor API로 수행한다. 하단 ‘후속 제작 기록’과 과거 결과물 README의 ‘연결하지 않았다’는 문구는 당시 상태이며 이 최신 완료 범위를 제한하지 않는다.

현재 주인공의 적용 경로는 Library `Assets/SpriteLibrarys/Protagonist.spriteLib`, Controller `Assets/Animations/Controller/Controller.controller`, 클립 루트 `Assets/Animations/Clib`이다. 2026-10-16 편집기에서 **Cheer 8개 카테고리·8개 클립·Cheer 상태와 자식8개의 Blend Tree가 연결됨**을 확인했다. 다른 캐릭터는 해당 캐릭터별 에셋을 사용한다.

## 1. 확정한 표현 방식

- Unity 6.5 기반 비도트 2D 탑다운 게임. 라그나로크처럼 방향에 따라 그림이 바뀌는 방식을 참고하되 도트 화풍은 사용하지 않는다.
- 필드 캐릭터의 기본 방향은 앞·뒤·좌·우·대각선 4개를 합친 8방향이다.
- 제작 방식은 프레임별 스프라이트 교체다. 이전의 파츠 리깅 실험을 기본 제작 방식으로 되돌리지 않는다.
- 일반 필드 캐릭터도 승인된 성인 비율을 유지한다. 임의로 SD·치비·큰 머리 비율로 변경하지 않는다.
- 전투 장면은 없다. 걷기, 시선, 손짓, 표정, 감정 변화, 물건 전달 등 일상과 관계 표현을 우선한다.
- 용사들은 주식시장에 참여하지 않으며 처음에는 후원자가 누구인지 모른다. 용사를 시장 거래자로 그리는 연출이나, 일반 교류가 곧바로 후원자 정체 공개가 되는 연출을 임의로 추가하지 않는다.

## 2. 화풍과 색

- 연하고 맑은 채색, 선명하게 읽히는 색을 사용한다. 원화의 따뜻하고 섬세한 선과 부드러운 셀 채색을 기준으로 한다.
- 같은 캐릭터의 방향·동작·프레임에서 얼굴, 머리 모양, 머리 크기, 체격, 선 굵기, 팔레트, 조명 방향을 유지한다.
- 천과 조끼는 무광으로 표현한다. 유광 하이라이트, 반짝이는 재질, 과도한 피부 광택을 추가하지 않는다.
- 스프라이트에서는 미세한 직물 무늬, 종이 질감, 입자, 빗금, 무작위 잔주름을 줄인다.
- 움직이지 않는 부위의 넓은 명암과 주름은 고정한다. 프레임마다 명암과 외곽선을 다시 해석해 생기는 반들거림·자글거림을 불합격 사유로 본다.
- 인물별 개성은 유지하되 몸통이나 어깨를 임의로 넓히거나 근육을 더하지 않는다.

## 3. 캐릭터 기준

### 주인공

- 평범하게 생긴 성인 남자. 특별한 능력자나 근육질 영웅처럼 바꾸지 않는다.
- 짧고 자연스럽게 흐트러진 짙은 갈색 머리, 갈색 눈, 안경·수염 없음.
- 아이보리색 열린 칼라 셔츠, 팔뚝까지 걷은 소매, 회갈색 조끼, 갈색 벨트·바지·낮은 구두.
- 묶인 갈색 주머니는 **해부학적 왼쪽 허리**에 고정한다. 화면의 같은 쪽에 붙이는 규칙이 아니다. 방향 전환 시 위치와 가림 관계를 확인한다.
- 장부는 필요할 때 사용하는 소품이다. 기본 Idle·걷기는 빈손이며 장부를 손에 영구히 붙이지 않는다.
- 기준 원화: `Assets/Images/Illustration/Underwrite_주인공_컨셉_v2.png`.
- 현재 필드 기준: `Assets/Images/Characters/Protagonist/Idle`의 스프라이트. 기존 Idle의 잔주름·윤곽 흔들림까지 복제하지 않는다.

### 용사 5명

| 캐릭터 | 유지할 특징 |
|---|---|
| 인간 남자 | 안경을 쓴 범생이 인상. 주인공과 다른 얼굴·복장·성격이 읽혀야 한다. |
| 인간 여자 | 인간 남자·엘프보다 작고 호리호리함. 여성스러운 외모와 표독하고 날카로운 인상. 넓은 어깨나 강한 덩치로 바꾸지 않는다. |
| 엘프 여자 | 길고 곧은 자주색 생머리, 작은 편의 뾰족한 귀, 늘씬한 체형. 승인된 개성 있는 성인 디자인을 따른다. |
| 워리어 남자 | 가장 크고 건장한 체격. 승인된 남성 디자인을 유지한다. |
| 페어리 여자 | 가장 작고 귀여운 인상. **귀는 인간처럼 정상적인 위치와 형태**로 그린다. |

키 순서: **워리어 > 엘프 = 인간 남자 > 인간 여자 > 페어리**. 인간 여자는 작게 조정한 최종 비율을 기준으로 한다.

용사 기준 원화: `Assets/Images/Illustration/Underwrite_용사5인_컨셉_v10.png`. 이전 버전의 엘프 웨이브 머리를 되살리지 않는다.

## 4. 방향과 동작

| 코드 | 화면에서의 방향 | DirectionX | DirectionY |
|---|---|---:|---:|
| S | 정면 | 0 | -1 |
| SE | 오른쪽 앞 대각선 | 0.707 | -0.707 |
| E | 오른쪽 옆면 | 1 | 0 |
| NE | 오른쪽 뒤 대각선 | 0.707 | 0.707 |
| N | 뒷면 | 0 | 1 |
| NW | 왼쪽 뒤 대각선 | -0.707 | 0.707 |
| W | 왼쪽 옆면 | -1 | 0 |
| SW | 왼쪽 앞 대각선 | -0.707 | -0.707 |

- 앞 대각선과 뒤 대각선을 혼동하지 않는다. 왼쪽 방향이 오른쪽 방향으로 재생성되지 않았는지 코·발·등을 확인한다.
- 비대칭 주머니와 의상 때문에 좌우 반전을 무조건 최종 원화로 사용하지 않는다.
- Idle은 방향별 정지 원화가 아니라 반복 가능한 작은 호흡·눈 깜빡임 동작이다. 뒤에서는 어깨·옷의 작은 변화로 표현한다.
- 걷기는 반대 팔·다리의 교차, 접지·통과 자세, 무릎 굽힘과 체중 이동이 보여야 한다. Idle에 발만 흔드는 것으로 대신하지 않는다.
- 8방향 걷기는 같은 보행 주기를 다른 시점으로 투영한다. 방향별 같은 프레임 번호에서 선행 팔·다리의 해부학적 좌우가 맞는지 대조한다. 특정 대각선만 팔꿈치를 배 높이로 접거나, 양팔이 거의 고정되거나, 팔 교차 순서가 달라지는 결과를 완료로 처리하지 않는다.
- 대박 모션은 놀람·기대 → 힘 모으기 → 두 주먹을 들고 기뻐하기 → 착지·정리의 흐름을 우선 검토한다. 얼굴만 웃는 동작으로 끝내지 않는다.
- 큰 감정 동작의 제작 방향은 별도 범위로 기록한다. 정면만 만들었으면 8방향 완료라고 부르지 않는다.

## 5. 프레임과 좌표

- 머리·팔·다리의 실제 길이와 인물 체격을 고정한다. 동작 때문에 달라진 실루엣을 키 변화로 오인해 매 프레임 따로 확대·축소하지 않는다.
- 같은 동작의 프레임은 동일한 캔버스 크기·해상도·PPU·피봇 기준을 사용한다.
- 현재 Idle 출력 규격은 프레임당 **362×724px**, 발밑 기준은 위에서 711px, 중심 X는 181px다. Unity의 아래쪽 좌표로는 기준점 (181, 13)이다.
- 이번 걷기 시안은 큰 보폭이 잘리지 않도록 **640×724px**, 공통 기준점 (320, 13)으로 출력한다. 대박 시안은 **512×960px**, 공통 기준점 (256, 13)을 사용한다. 캔버스 여백 차이는 캐릭터 키의 차이가 아니다.
- 걷기의 몸통 중심과 접지 기준을 유지한다. 앞뒤로 뻗는 발에 따라 프레임을 매번 좌우로 재정렬하면 골반이 흔들릴 수 있으므로 확인한다.
- 점프·웅크리기·손 들기에는 더 큰 공통 캔버스를 허용한다. 뛰어오른 발을 매 프레임 바닥에 다시 맞추지 않는다. 점프 높이와 신체 크기를 분리한다.
- 고정 캔버스를 유지하고 개별 Trim은 필요할 때만 사용한다. Trim 후에도 원래 캔버스의 공통 기준점을 새 사각형의 피봇으로 환산한다.
- 정지 미리보기뿐 아니라 실제 반복·일회 재생을 확인한다. 끝 프레임에서 첫 프레임으로 돌아갈 때 튀지 않아야 한다.

## 6. 알파와 가장자리

- PNG RGBA를 사용한다. 실루엣 바깥은 **알파 0**, 인물 내부는 불투명, 가장자리만 좁은 안티앨리어싱을 사용한다.
- 바닥·접지 그림자, 광원 후광, 안개, 반투명 배경, 체크무늬 배경, 떠 있는 점·선은 캐릭터 원본에 넣지 않는다.
- 기본 후처리 기준은 알파 32 미만 제거다. 머리카락·손가락 등 세부가 잘리지 않는지 반드시 재검사한다. 기준값을 일괄 높이는 것으로 품질 문제를 숨기지 않는다.
- 각 프레임의 캐릭터 본체와 떨어진 잡픽셀을 제거한다. 분리된 소품이나 의도된 효과가 있을 때는 본체 하나만 남기는 처리를 무조건 적용하지 않는다.
- 완전 투명 픽셀의 숨은 RGB도 정리해 텍스처 보간 시 색 테두리가 비치지 않도록 한다.
- 검은 배경과 밝은 배경에서 테두리를 모두 확인한다. 흰 테두리, 검은 번짐, 잘린 손·귀·신발을 검사한다.
- 생성 도구의 투명 배경 옵션만으로 잔점 0개를 보장하지 않는다. 연결 성분·알파·가장자리 접촉을 검사하고 결과를 저장한다.
- 사용자는 PNG의 알파 잔점 정리를 코드로 수행하는 것을 허용했다. 새 그림·표정·동작은 이미지 생성 도구로 제작하며, 변형 코드로 완성 원화를 대신했다고 주장하지 않는다.

## 7. Unity 전달과 자글거림 점검

- 비도트 스프라이트는 Bilinear를 기본 검토값으로 삼는다. 도트용 Point 필터나 Pixel Perfect 설정을 무조건 적용하지 않는다.
- 작업 검증은 압축 없는 원본으로 진행하고, 최종 압축은 실제 표시 크기에서 따로 비교한다.
- 알파 사용·Alpha Is Transparency, Mipmap 비활성, 일관된 PPU·공통 피봇을 확인한다. 임포트 해상도가 원본을 축소하고 있지 않은지 검사한다.
- 옷이 자글거리면 원화 자체의 프레임별 명암 차이, 잘림·피봇 차이, 텍스처 압축, 실제 화면 축소, 조명·머티리얼을 나눠 확인한다. 원화 확인 없이 조명 문제라고 단정하지 않는다.
- 재생 속도는 동작별로 기록한다. 기존 Idle 미리보기는 6프레임을 900/350/80/110/120/700ms로 유지해 2.26초로 재생한다. 전 프레임을 같은 시간으로 재생하면 느낌이 달라진다.
- `.meta`, `.anim`, `.asset`, `.prefab`, `.unity`를 텍스트 편집으로 변경하지 않는다. 실제 변경은 연결된 Unity Editor API를 사용한다.
- 사용자가 만든 Animator·Sprite Library·Clip 연결과 에셋 GUID를 보존한다. 기존 결과를 덮어쓰기 전에 변경 범위를 기록한다.
- **현재 사용자의 후속 수정 지시:** 필드 걷기 이미지는 `Assets/Images/Characters/Protagonist/Walking/{E,N,NE,NW,S,SE,SW,W}`에 분류되어 있다. 원화 수정 시 해당 방향의 기존 파일명에 **PNG만** 덮어써서 바로 확인할 수 있게 한다. `.meta`는 Editor API로도 변경하지 않는다. 해상도·프레임 수·파일명을 유지하고, 작업 전후 메타 파일의 해시를 비교한다. 이 지시는 일반적인 새 버전 폴더 납품보다 우선한다.

## 8. 납품·보관

- 프로젝트에서 쓸 최종 PNG는 프로젝트 폴더에 보관한다. 생성 도구 기본 출력 경로에만 남기지 않는다.
- 승인 전 결과는 시안으로 표시하고, 완료한 방향 수·프레임 수·남은 차이를 명시한다.
- 원본 생성 이미지, 참조 이미지, 전체 프롬프트, 후처리 방식, 방향·프레임 순서, 재생 시간, 미리보기, 검증 결과를 함께 기록한다.
- 기존 파일은 임의로 덮어쓰지 않고 동작·버전별 새 경로를 사용한다. 사용자가 정리·삭제한 실험용 리깅 자산을 다시 복구하지 않는다.
- 완료 기준: 캐릭터 일치, 방향 일치, 감정·동작 가독성, 시간적 명암 안정성, 접지·피봇 안정성, 알파 잔점·잘림 없음, 실제 재생 확인.

## 9. 이번 작업의 범위

- 기존 Idle의 자글거림 원인을 조사하고 재현 가능한 점검 기록을 남긴다.
- 주인공 걷기: 8방향 스프라이트 애니메이션 시안 제작.
- 주인공 대박: 정면의 큰 감정 동작 시안 제작. 8방향 전체 완료로 표시하지 않는다.
- 기존 Idle과 Animator 설정은 새 동작 제작을 위해 무단 교체하지 않는다.
